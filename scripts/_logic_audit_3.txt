========================================================================
STATUS: MAJOR

Issues found:
  - [MISSING SOURCE] New only covers SSE (上交所) and SZSE (深交所). Old also covers BSE (北交所) via ipo_bse_spider.py and ipo_east_spider.py. New has NO 北交所 coverage.
  - [MISSING FIELD - SSE] Old extracts `city = issuer['s_areaNameDesc']` (ipo_sse_spider.py L82). New does not extract city at all.
  - [MISSING FIELD - SSE & SZSE] Old sends separate API request to fetch full `ipo_status` (IPO process timeline with publish_date + examine_status per stage). New only uses `examine_status` as `ipo_status`, losing the full timeline (ipo_sse_spider.py L141-161, ipo_szse_spider.py L107-116).
  - [MISSING FIELD - SZSE] Old item model has `register_status` field (finance_item.py L289). New item does not have this field at all.
  - [URL DIFFERENCE - SZSE] Old uses `pageIndex={page}` where page is 0-based (start_page-1). New uses `pageIndex={page-1}`. Both result in 0-based. OK.
  - [SSE - Attachment file_type] New maps empty string to `问询与回复` in _SSE_FTYPE. In old, file_type is set to '' (empty) for disclosureMaterials, then overridden by res['matnm'] if non-empty (ipo_szse_spider.py L133). For SSE, old and new both use the same _SSE_FTYPE mapping. Same behavior, OK.
  - [BSE - NOT COVERED] Old BSE spider (ipo_bse_spider.py) fetches from bse.cn with its own token/status mapping, handles xxgkInfo file categories differently (FYYJS/GPFXBJS/GPFXSMS/GPZJXCGPTJS/SJBG with BHG/SBG/SYG versions). All missing in new.
  - [MD5] Same formula: entity_name + str(update_date) + examine_status. OK.
  - Both SSE/SZSE use same Attach MD5: ipo_md5 + attach_title + publish_date. OK.

7. SPIDER: Person Pedia (personal_character_encyclopedia + entity_staff_number)
   NEW: person_pedia_spider.py  |  OLD: askci_spider.py
========================================================================
STATUS: MAJOR

Issues found:
  - [MISSING FIELDS - person_pedia] Old extracts 15 fields. New sets these as EMPTY strings:
      stock_name          = ''  (old: data['stock_name'])
      appoint_enterprise  = ''  (old: data['entity_name'])
      appoint_end_date    = ''  (old: extract from td[5])
      brief_introduction  = ''  (old: extract from td[11]/p)
      salary              = ''  (old: extract from td[9])
      hold_stock_num      = ''  (old: extract from td[10])
    This is a critical regression — 6 fields are completely lost.
  - [MD5 ORDER BUG] Old: md5(stock_code + person_name). New: md5(name + code). The ORDER of concatenation is REVERSED (askci_spider.py L83 vs person_pedia_spider.py L60). This produces a DIFFERENT md5 hash, effectively losing dedup continuity. Existing records cannot be de-duplicated against.
  - [XPATH DIFFERENCE - detail] New adds fallback selector `//div[@class="person_table"]//tr` which old does not have. This is a potential enhancement not regression.
  - [XPATH - column mapping] New uses union selectors (e.g. `./td[3]/text()|./td[2]//text()`) that try to handle two different table layouts. Old uses fixed indices. The fallback indices may pick wrong cells for certain formats.
  - [Staff - Missing fields] Old extracts `entity_name` and `sample_type` fields. New has them as empty strings.
  - [Staff - XPath] Old uses `//table[@border="1"]/tbody/tr`. New uses `//table//tr` (broader match, potential false positives from other tables on page).
